# OP-52 plan — MLCC DC-bias and temperature curves from vendor sites

Goal: for each capacitor MPN on the schematic, fetch the vendor's own
capacitance-vs-DC-bias and capacitance-vs-temperature curves over plain HTTP
(no browser automation), store them in the datasheet spec cache, and feed them
to the analyzers that already read `curves.C_bias`.

Decided with the user (2026-11-21): fetch from the vendor sites, no
Playwright. Research first (this file), implementation later.

## Research results (2026-11-21, probed with curl)

None of these endpoints is a documented public API. They are the JSON
back-ends of each vendor's own web tool, so they can change without notice.
Each fetcher therefore needs a "format changed" error, and a live test under
`-m network`.

### Murata — SimSurfing: works, best source

- `GET https://ds.murata.com/simserve/characteristics` with query parameters
  `callback=nothing`, `WorkInfo=x` and:
  - `ReqType=IsExistPartnumber&partnumbers=<pn>` →
    `[{"existence":"true"|"false"}]`. Use the base MPN without the packing
    code (e.g. `GRM21BR61E106KA73`; a trailing `#` is accepted too).
  - `ReqType=GetProductInfo&partnumbers=<pn>` → category (`mlcc`) and the
    MPN without packing code.
  - `ReqType=Characteristics&ReqChara=[{"partnumber":"<pn>","chara_type":"<t>","parameter":{...}}]`
    → `JsonCharaData[0].charadata[0]`. That object has `caption2`
    (the conditions, e.g. "capchange, 25.0degC, AC1.0Vrms"), `x_unit`
    (`V` / `degC`), `y_unit` (`%`), `error` (empty on success) and `data` as
    `[[[x],[y]], ...]` (about 200 points).
- `chara_type`: `c_dcbias_capchange` (DC bias, %), `c_temp_capchange`
  (temperature, %). The config lists `c_acvoltage_capchange`, `temp_rise`,
  `z`, `r` and `s11` too.
- `parameter` can include `"tc":"85"`. That gives the DC-bias curve
  measured at 85 °C (GRM21BR61E106KA73 at 12 V: −80 % at 85 °C). So the
  combined V × T effect comes from measurement, not from multiplying the two
  curves. `ac` accepts only listed values; an unlisted one returns
  `error: "Specified AC is not matched with the options"`.
- A CSV twin exists at `/simserve/characsvdownload?ReqType=characsv&...`.
  The JSON is easier; use it.
- No auth, no cookies. `robots.txt` is 404 (no restriction stated).
- Covers Murata MLCC (GRM, GCM, GJM, GRT, GA3, KC…), polymer and
  molded caps (`polymercapacitors`, `moldingsmdcap` categories).

### Samsung Electro-Mechanics — Component Library: works

- `GET https://weblib.samsungsem.com/mlcc/mlcc-ec-data-sheet.do?partNumber=<pn>`
  (full MPN, e.g. `CL21A106KAYNNN`). This is an HTML page (~165 kB) with the
  graph data embedded as JSON. Each block has `"graphType"`: `"DCBias"`,
  `"TCC"`, `"ACVolt"`, `"RippleCurr"` or `"|Z|_R"`. A block holds
  `selectPartsList[].chartList[].data` = `[{"x":"…","y":"…"}]` (strings)
  plus its conditions (`vdc`, `degC`, `dsDcFre`, `asixYOption: "DeltaC"`).
- Parse the JSON blocks out of the page; do not scrape the HTML layout.
- `robots.txt`: `User-agent: * Allow: /`.
- Still to check during implementation: whether there is a second endpoint
  behind the page (the page script calls `semChart.afterGetData`), and
  whether DC bias at a temperature other than 25 °C is available.

### KEMET (Yageo group) — K-SIM: works, modelled data

- `POST https://ksim3.kemet.com/pn`, JSON
  `{"partNumber":"<pn>","method":"search","session":"<uuid>"}` → the part
  record (`kemetPn`, `capValue`, `dielectric`, `voltageRating`,
  `param.bias` / `param.tempAmbient` with their limits). Returns
  `"No match found."` for a non-KEMET part.
- `POST https://ksim3.kemet.com/plot`, JSON body:
  `{"plotType":"Vbias"|"TCC"|"VCAC", "parts":[<part record>], "freqList":[1000],
  "calculated":"No", "combine":"No", "highlight":0, "ind":0, "line":"50",
  "path":"Shunt", "res":0, "spiceFileFormat":"CKT", "spiceFreq":1000,
  "start":100, "stop":1e9, "tempRise":20, "session":"<uuid>"}` →
  `seriesList[].points` = `[{"x","y"}]`, `yLabel` "Capacitance Change",
  `yUnit` "%".
- The bias and ambient temperature for each part are set in
  `part.param.bias.select` and `part.param.tempAmbient.select`. Check during
  implementation that `Vbias` at another temperature changes the curve.
- K-SIM output is **calculated from KEMET's model**, not measured. Record
  this as `"method": "model"`.
- TCC came back all zeros for `C0805C106K4PACTU` (X5R). Treat an all-zero
  series as "no data", not as "flat".
- The front-end also logs to `/log/part`. The fetcher does not call it.
- Yageo `CC…` part numbers are not in K-SIM ("No match found").

### TDK — blocked

- `product.tdk.com` (part pages, characteristic search and catalog PDFs)
  returns `403 Access Denied` (Akamai bot protection) to any non-browser
  client. **Do not try to get around it.** TDK parts fall back to:
  - a user-downloaded characteristics CSV, imported with the same tool from
    a local path, or
  - the datasheet extraction flow (`C_bias` / `C_temp` read off a PDF the
    user provides).

### Taiyo Yuden — TY-COMPAS: reachable, endpoint not yet mapped

- `https://ds.yuden.co.jp/TYCOMPAS/ut/detail?pn=<pn>&u=M` serves 200.
  The front-end JS (`/TYCOMPAS/js/min/app.min.js`) names REST endpoints
  relative to `/TYCOMPAS/ut/`: `graphRest`, `charactericticGraph`,
  `graphUnit`, `graphcsv`.
- `graphRest?pn=…` answers with a 500 and a gzipped JSON error, so the
  endpoint exists but the parameters are wrong. Map the parameters from the
  calls in `app.min.js` during implementation.

### Not probed yet

- Kyocera AVX SpiCAT (`spicat.kyocera-avx.com` answers), Würth REDEXPERT,
  Yageo's own site (`yageogroup.com/products?search=` answers), Vishay.
  Check these after the four above; leave them out if a source needs a
  login or a browser.

## Design

- **Adapter** `src/kicad_claude/adapters/cap_curves.py`: one fetcher per
  vendor, plus an MPN router by prefix. For example: GRM / GCM / GJM / GRT /
  GA3 → Murata; CL → Samsung; C0402… C1210 with a KEMET suffix → KEMET;
  EMK / JMK / LMK / TMK / UMK → Taiyo Yuden; C1005 / C2012 / CGA → TDK.
  The manufacturer field (`Manufacturer`, from the BOM / sourcing data) wins
  over the prefix. Use the existing HTTP client from `datasheet_fetch.py` /
  the sourcing adapters (`quiet_http`). No new dependency.
- **Store** in the spec cache record of the MPN (`datasheet_specs.specs_path`):
  - `curves.C_bias`: at 25 °C (existing key, so existing consumers work
    unchanged);
  - `curves.C_temp`: new key, x in `degC`, y in `%` (0 at 25 °C);
  - `curves.C_bias_at`: `{temp_c: CURVE}`, DC bias at other temperatures
    where the vendor supports it (Murata `tc`, KEMET `tempAmbient`).
  - Each CURVE keeps the existing format and adds `source` (vendor, URL,
    fetch date), `method` (`measured` / `model`) and `conditions` (AC level,
    frequency, temperature).
  - Downsample to about 30 points (keep the end points and monotonic shape).
  - A fetched record must never overwrite a curve that was extracted from a
    PDF. Keep both, keyed by source, and prefer the vendor curve.
- **Helper** `c_eff_ratio(rec, volts, temp_c)` in `datasheet_specs.py`:
  1. use `C_bias_at` at the nearest bracketing temperatures and interpolate;
  2. else `bias(V) × (1 + temp(T)/100)`, flagged `approx: true`.
- **Tool** in the `datasheets` set (`tools/datasheets.py`), e.g.
  `fetch_cap_curves(refs: list[str] | None, mpns: list[str] | None,
  temps_c: list[float] | None, refresh: bool = False)`. The default is every
  fitted capacitor of class II dielectric (from value, description or
  dielectric field), or any capacitor ≥ 1 µF. Return per MPN: vendor,
  status (`fetched` / `cached` / `not_found` / `blocked` / `unsupported`),
  and C at the rail voltage if known. Throttle about one request per second
  per host, and cache. Never send anything but the MPN.
- **Consumers**:
  - `emc_review` PDN bank, `spice_auto` and the thermal DC-bias check: use
    `c_eff_ratio` with the board temperature estimate (`board_thermal`)
    where there is one, else 25 °C.
  - New finding, e.g. `CR-CAP-CEFF` (or in `review_part_ratings`): C_eff at
    the rail voltage and temperature falls below a minimum the regulator
    datasheet gives (`C_out_min` in the regulator's spec record), or below
    a caller-given minimum.
- **Tests**:
  - Unit tests with saved vendor responses (fixtures, one per vendor,
    trimmed) for the parsers.
  - `-m network` tests: one live MPN per vendor.
  - A test that a TDK MPN returns `blocked` without retrying.
